## 一、概述

### 1.1 中间件在航天软件架构中的位置

航天软件架构通常分为三层：

```
┌─────────────────────────────────────────────────────────┐
│                   应用层 (Applications)                  │
│  卫星控制 │ 载荷管理 │ 通信协议 │ 自主导航 │ AI 推理      │
├─────────────────────────────────────────────────────────┤
│                中间件层 (Middleware) ← 本章重点          │
│  通信协议 │ 数据分发 │ 服务总线 │ 容错管理 │ 时间同步    │
├─────────────────────────────────────────────────────────┤
│                  操作系统层 (OS)                         │
│  Space Grade Linux │ Zephyr RTOS │ VxWorks │ RTEMS      │
└─────────────────────────────────────────────────────────┘
```

### 1.2 航天中间件的主要类别

| 类别 | 功能 | 典型代表 |
|------|------|---------|
| **通信协议中间件** | 实现航天器内部/外部通信 | CCSDS 协议栈、SpaceWire、DDS |
| **星务软件/飞行管理** | 卫星平台管理、姿态轨道控制 | cFS、F Prime 框架 |
| **载荷平台软件** | 有效载荷控制与数据处理 | 专用载荷框架、 kubOS 遗产 |
| **容错/冗余中间件** | 故障检测、三模冗余、恢复 | TMR 软件、看门狗管理 |
| **时间同步中间件** | 星上时间管理、同步 | IRIG-B、PTP、CCSDS 时间码 |
| **数据分发服务** | 发布/订阅模式数据分发 | OpenDDS、eProsima Fast DDS |

## 二、通信协议中间件

### 2.1 CCSDS 协议族

**CCSDS**（Consultative Committee for Space Data Systems，空间数据系统咨询委员会）是国际航天领域最重要的通信协议标准组织。

#### 2.1.1 CCSDS 核心协议

```
CCSDS 协议栈：
├── 空间链路层
│   ├── 空间数据链路协议（SDLS）
│   ├── COP-1（同步轨道）
│   └── COP-P（近距轨道）
├── 网络层
│   ├── 空间通信协议（SCPS-NP）
│   └── 延迟/中断容忍网络（DTN）
├── 应用层
│   ├── 空间文件传输协议（CFDP）
│   ├── 空间超文本传输协议（SCPS-TP）
│   └── 空间包协议（Space Packet Protocol）
└── 跨层服务
    ├── 空间通信安全
    └── 空间目录服务
```

| 项目名称 | 来源 | 协议支持 | 语言 | 状态 |

| **COSMOS** | Ball Aerospace | Space Packet | Ruby/C | 活跃维护 |

### 2.2 SpaceWire 协议栈

**SpaceWire** 是 ESA 主导的高速串行通信标准，广泛应用于欧洲及国际航天器。

#### 2.2.1 SpaceWire 特性

- **速率**: 2 Mbps ~ 400 Mbps
- **拓扑**: 点对点、星型、网型
- **路由**: 基于目的地地址的逻辑路由
- **容错**: 链路级错误检测与恢复

| **RTEMS SpaceWire** | RTEMS | C | 官方支持 |
| **PySpaceWire** | Linux/Windows | Python | 测试工具 |

### 2.3 DDS（Data Distribution Service）

**DDS**（数据分发服务）是 OMG 标准，采用发布/订阅模式，适用于分布式实时系统。

#### 2.3.1 DDS 架构

```
┌─────────────────────────────────────────────────────────┐
│                     DDS 应用层                           │
│  发布者 (Publisher)          订阅者 (Subscriber)         │
│     │                           │                       │
│  DataWriter                DataReader                   │
│     │                           │                       │
├─────────────────────────────────────────────────────────┤
│                   DDS 中间件层                           │
│  ┌─────────────┬─────────────┬─────────────────────┐   │
│  │  可靠性层   │  持久性层   │   发现服务          │   │
│  │  (Reliable) │  (Durability)│  (Discovery)       │   │
│  └─────────────┴─────────────┴─────────────────────┘   │
│                   全局数据空间                         │
│              (Global Data Space)                       │
└─────────────────────────────────────────────────────────┘
```

#### 2.3.2 开源 DDS 实现

| 实现 | 组织 | 许可 | QoS 支持 | 航天应用 |
|------|------|------|---------|---------|
| **OpenDDS** | Object Computing Inc. | GPL/商业 | 完整 | 研究/教育 |
| **eProsima Fast DDS** | eProsima (Eprosima) | Apache 2.0 | 完整 | CubeSat |
| **Cyclone DDS** | ADLINK Technology | EPL/商业 | 完整 | 欧洲航天 |
| **Zenoh** | Eclipse Foundation | EPL 2.0 | 基础 | 新兴项目 |

#### 2.3.4 DDS QoS 配置详解

DDS 的核心优势在于其丰富的 QoS（服务质量）策略：

```xml
<!-- Fast DDS 配置示例：卫星星座间通信 -->
<profiles xmlns="http://www.eprosima.com/XMLSchemas/fastRTPS_Profiles">
  <data_writer profile_name="SatelliteTelemetryWriter">
    <qos>
      <reliability>
        <kind>RELIABLE_RELIABILITY_QOS</kind>
        <max_blocking_time>
          <sec>1</sec>
          <nanosec>0</nanosec>
        </max_blocking_time>
      </reliability>
      <durability>
        <kind>TRANSIENT_LOCAL_DURABILITY_QOS</kind>
      </durability>
      <deadline>
        <period>
          <sec>0</sec>
          <nanosec>100000000</nanosec>  <!-- 100ms -->
        </period>
      </deadline>
      <liveliness>
        <kind>AUTOMATIC_LIVELINESS_QOS</kind>
        <lease_duration>
          <sec>2</sec>
        </lease_duration>
      </liveliness>
    </qos>
  </data_writer>
</profiles>
```

| QoS 策略 | 选项 | 航天应用场景 |
|---------|------|-------------|
| **可靠性** | BEST_EFFORT / RELIABLE | 遥测 (可靠) vs 视频流 (尽力而为) |
| **持久性** | VOLATILE / TRANSIENT_LOCAL | 历史数据回放、新节点加入 |
| **截止期限** | 时间值 | 实时控制回路超时检测 |
| **活性** | AUTOMATIC / MANUAL_BY_PARTICIPANT | 节点存活检测 |
| **优先级** | 1-120 级 | 关键命令优先传输 |

#### 2.3.5 DDS 在卫星星座中的应用

```
卫星星座 DDS 架构：
┌─────────────────────────────────────────────────────────┐
│                    地面站 (Ground Station)               │
│  DDS Router ←→ 卫星 ←→ 卫星 ←→ 卫星 ←→ DDS Router       │
│         ↑        ↓         ↓         ↓        ↑         │
│         └────────┴─────────┴─────────┴────────┘         │
│                    星间链路 (ISL)                        │
└─────────────────────────────────────────────────────────┘

DDS XRCE-DDP（有限资源客户端）：
- 适用于 CubeSat 等资源受限平台
- 代理模式：卫星运行轻量客户端，地面站运行代理
- 带宽优化：仅传输订阅数据
```

**2025-2026 年 DDS 航天应用进展**：
- **ESA Φ-lab**: 使用 Cyclone DDS 构建地球观测数据分发系统
- **商业星座**: 多家商业航天公司采用 Fast DDS 构建卫星间通信
- **中国实践**: 部分商业航天公司开始评估 DDS 用于星座管理

### 2.4 时间触发协议

#### 2.4.1 TTEthernet（时间触发以太网）

- **标准**: SAE AS6802
- **特点**: 微秒级时间同步，确定性传输
- **应用**: 深空探测、载人航天关键系统
- **开源状态**: 主要是商业实现（TTTech），开源研究项目有限

#### 2.4.2 IEEE 1588 PTP（精密时间协议）

- **精度**: 亚微秒级（硬件时间戳）
- **开源实现**:
  - **linuxptp**: Linux 用户空间实现
  - **OpenPTP**: 跨平台实现

```bash
# linuxptp 使用示例
sudo ptp4l -i eth0 -m -2
sudo phc2sys -s eth0 -c CLOCK_REALTIME
```

### 3.1 NASA cFS（Core Flight System）

**cFS** 是 NASA GSFC 开发的开源飞行软件框架，采用分层架构。

#### 3.1.1 中间件层架构

```
┌──────────────────────────────────────────────────────┐
│                  cFS 应用层                           │
│  姿态控制 │ 电源管理 │ 热控 │ 载荷接口 │ 通信管理    │
├──────────────────────────────────────────────────────┤
│                  cFE 核心框架 (中间件)                │
│  ┌──────┬──────┬──────┬──────┬──────┬──────┐        │
│  │  SB  │  ES  │  EVS │  TLM │  CMD │  TBL │        │
│  │软件总线│执行服务│事件服务│遥测  │命令  │表管理 │        │
│  └──────┴──────┴──────┴──────┴──────┴──────┘        │
├──────────────────────────────────────────────────────┤
│                  OSAL 抽象层                          │
│  进程 │ 线程 │ 信号量 │ 消息队列 │ 时间 │ 文件       │
└──────────────────────────────────────────────────────┘
```

#### 3.1.2 核心服务

| 服务 | 缩写 | 功能 |
|------|------|------|
| **软件总线** | SB | 基于消息的进程间通信 |
| **执行服务** | ES | 应用生命周期管理、监控 |
| **事件服务** | EVS | 事件日志、分级告警 |
| **遥测服务** | TLM | 遥测数据打包与下发 |
| **命令服务** | CMD | 地面命令接收与分发 |
| **表管理** | TBL | 配置参数管理、在轨更新 |

#### 3.1.3 应用示例

```c
// cFS 应用框架示例
#include "cfe.h"

void MY_AppMain(void) {
    CFE_SB_MsgId_t MsgId;
    CFE_SB_Buffer_t *SBBufPtr;

    // 注册接收消息
    CFE_SB_Subscribe(CFE_SB_ValueToMsgId(CFE_PLATFORM_CMD_MID), PipeId);

    while (RunStatus == CFE_ES_RunStatus_APP_RUN) {
        // 接收消息
        Status = CFE_SB_ReceiveBuffer(&SBBufPtr, PipeId, Timeout);

        if (Status == CFE_SUCCESS) {
            CFE_SB_GetMsgId(&MsgId, SBBufPtr);
            // 处理命令...
        }

        // 执行周期性任务
        MY_AppPeriodicTask();
    }
}
```

```python
# 伪代码：相机载荷管理中间件
class CameraPayload:
    def __init__(self):
        self.sensor = CameraSensor()
        self.processor = ImageProcessor()
        self.storage = DataStorage()

    async def capture_sequence(self, params):
        for i in range(params.count):
            # 采集
            raw_image = await self.sensor.capture(params.exposure)
            # 处理
            processed = await self.processor.process(raw_image)
            # 压缩
            compressed = await self.processor.compress(processed)
            # 存储/下发
            await self.storage.queue(compressed, priority=params.priority)
            # 遥测
            telemetry.send('CAPTURE', i, processed.size)
```

## 五、容错与冗余中间件

### 5.1 三模冗余（TMR）软件实现

软件 TMR 通过多副本执行和投票机制实现容错：

```
┌─────────────────────────────────────────────────────────┐
│                    应用任务                              │
│                      ↓ 复制                              │
│  ┌──────────────┬──────────────┬──────────────┐        │
│  │  副本 A      │  副本 B      │  副本 C      │        │
│  │  (Core 0)    │  (Core 1)    │  (Core 2)    │        │
│  └──────────────┴──────────────┴──────────────┘        │
│                      ↓ 投票                              │
│              ┌──────────────────┐                       │
│              │   投票器 (Voter)  │                       │
│              │  多数决/加权投票  │                       │
│              └──────────────────┘                       │
│                      ↓                                   │
│               输出/故障恢复                              │
└─────────────────────────────────────────────────────────┘
```

#### 5.1.1 软件 TMR 关键技术

| 技术 | 描述 | 实现难度 |
|------|------|---------|
| **数据复制** | 输入数据同步到多副本 | 低 |
| **时间同步** | 副本间执行时间对齐 | 中 |
| **投票算法** | 多数决、中值、加权投票 | 中 |
| **故障检测** | 超时、输出不一致检测 | 中 |
| **恢复策略** | 热备份切换、重启副本 | 高 |

### 6.2 时间同步协议

#### 6.2.1 IRIG-B 时间码

- **标准**: IEEE 1344
- **精度**: 毫秒级
- **应用**: 地面站、星内设备同步
- **开源实现**: 主要用于地面设备

#### 6.2.2 CCSDS 时间码

CCSDS 定义了多种时间码格式：

| 格式 | 长度 | 精度 | 应用 |
|------|------|------|------|
| **CDS 时间码** | 64 位 | 毫秒 | 通用 |
| **精简时间码** | 32 位 | 秒/分 | 低带宽 |
| **扩展时间码** | 96 位 | 微秒 | 高精度 |

#### 6.2.3 PTP（IEEE 1588）在航天

- **精度**: 亚微秒（硬件时间戳）
- **开源实现**: linuxptp
- **航天应用**: 星内网络同步、分布式载荷

### 6.3 开源时间同步实现

```c
// PTP 时间同步示例（linuxptp）
struct ptptimer {
    struct clockid_t clock_id;
    struct timespec current_time;
    int offset_ns;  // 与主钟的偏移
};

void synchronize_to_grandmaster(struct ptptimer *timer) {
    // 获取主钟时间
    clock_gettime(CLOCK_TAI, &timer->current_time);
    // 应用偏移校正
    timer->current_time.tv_nsec += timer->offset_ns;
    // 设置本地时钟
    clock_settime(timer->clock_id, &timer->current_time);
}
```

## 七、综合对比与选型建议

### 7.1 通信协议中间件对比

| 协议 | 带宽 | 实时性 | 复杂度 | 适用场景 |
|------|------|--------|--------|---------|
| **CCSDS Space Packet** | 中 | 中 | 中 | 通用航天器 |
| **SpaceWire** | 高 | 高 | 中 | 欧洲任务、高速载荷 |
| **DDS** | 高 | 高 | 高 | 分布式系统、星座 |
| **CAN 总线** | 低 | 高 | 低 | 小卫星内部总线 |

### 7.2 星务软件选型

| 任务类型 | 推荐框架 | 理由 |
|---------|---------|------|
| **CubeSat/纳卫星** | F Prime | 敏捷开发、工具链完善 |
| **小型卫星（50-500kg）** | cFS | 成熟稳定、文档丰富 |
| **大型卫星** | 定制 + DDS | 灵活集成、高性能 |
| **商业快速原型** | F Prime on Linux | 快速迭代、地面验证便利 |

### 7.3 容错中间件选型

| 关键性等级 | 推荐方案 |
|-----------|---------|
| **非关键** | 单层看门狗 + 重启恢复 |
| **一般关键** | 双层看门狗 + 热备份 |
| **高关键** | 软件 TMR + FDIR |
| **生命攸关** | 硬件 TMR + 软件 TMR + 形式化验证 |
